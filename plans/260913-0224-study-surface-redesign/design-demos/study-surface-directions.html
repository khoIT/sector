The surface has two summary systems, and they are copying each other

Measured on the live page: five facts, stated twelve times, across four full-width status rows before any work begins. Here is the audit, three ways out, and the one I would build.

Three more things the capture shows, which nobody asked about but which the same fix resolves:

  • The findings card is the smallest block on the page. One row, boxed top-right, while the media viewer takes ~340px on the left. The findings are the product; the upload is logistics.

02 · Diagnosis

Nobody designed this. It accreted.

The study bar replaced a four-step stepper, and that was the right call: it answers what is still missing instead of where am I. But afterwards each panel learned to summarise itself — files fold to a count, scan type folds to a name.

So the page now runs two summary systems at once: a bar that summarises the panels, and panels that summarise themselves. Every fold I add to a panel creates a new duplicate of a chip in the bar. The last one shipped yesterday.

Summary belongs to exactly one layer. This is not a styling problem and it will not be fixed by rewording chips — whichever layer keeps the job, the other has to stop doing it.

So the rule for everything below: one fact, one place — unless the second place does a genuinely different job. Only two qualify: a fact that is off-screen when you need it (that earns a sticky bar), and a fact restated at the point of no return (that earns a line on the submit screen).

Four status rows become one. Each chip is the control — it opens the thing inline instead of scrolling to a copy of it.

For

  • Smallest diff of the three. Nothing moves; rows are deleted.
  • Removes ~130px of chrome and five of the twelve statements immediately.
  • The warning moves next to the findings, where it belongs.

Against

  • One strip doing four jobs. It is already crowded at 1280 and this adds a chip.
  • Groups still appears twice — the chip and the panel — and the panel cannot simply go (see the risk below).
  • Upload is still not given space of its own; it just got smaller.
  • Leaves the two-summary-systems architecture in place. The next fold re-creates the bug.
Direction B · recommended

The media is the constant; everything else is the work. Give each a column and delete the bar entirely.

The rail is the file list — there is no Files card. The bar is gone, so exam and groups each appear exactly once. The footer sticks, so submit never leaves.

For

  • Removes the duplication structurally. There is no bar left to duplicate anything — it is not a wording fix that can regress.
  • Upload gets literally its own space, and leaves the reading order of the work. Drag-and-drop still works page-wide.
  • It is the geometry the app already committed to. The reviewer's scan-detail page is media-left / form-right, and the interpretation panel already says so in its own comment. This makes creating and reviewing a study the same shape.
  • Findings get full height beside the media instead of a box in a corner.
  • The sticky footer fixes submit going off-screen, which nothing does today.

Against

  • Biggest diff. StudySurface is rewritten; StudyBar is deleted.
  • Must stack below ~1280 — media first, then work — so the laptop-width layout has to be designed, not inherited.
  • A fresh study opens with an empty rail. That empty state has to carry the “drop files here” job on its own and be good.
  • The work column is narrower, so the 22-tile exam grid needs a different expanded form.

Upload is one line at the bottom edge that expands on drag. Metadata is one line at the top.

For

  • Maximum focus on the one thing that is actually teaching material.
  • Upload never leads and never blocks — the least intrusive of the three.
  • Shortest page by a wide margin.

Against

  • It hides two choices that cannot be undone. Exam type and group routing are both fixed at creation — the API has no route to change either afterwards.
  • And the safety net is missing. In this flow the submit screen never restates groups (verified below), so a collapsed tray would be the only place routing is ever shown.
  • Two docked bars eat vertical space on a 13" laptop, where the page is thinnest.
  • A docked upload lane is the easiest place to hide a failed upload.

04 · Recommendation

Build B

A and C both treat the symptom. A edits the chips; C hides them. Only B removes the thing that generates duplicates — with the bar gone there is no second summary layer, so the next panel that learns to fold cannot re-create this.

And B is not a new idea imported from outside: it is the geometry this app already uses to read a study. Making creation the same shape as review is the kind of consistency a learner feels without being able to name it.

C is the more exciting design and I would want it if group routing were reversible. It is not, and the submit screen does not currently name it, so C trades a real safety property for polish. That is the wrong trade on patient-adjacent work.

What it costs

  1. StudySurface rewritten as two columns plus a sticky footer — roughly 120 lines.
  2. StudyBar / StudyChip deleted, along with the jump-scroll helper and its flash.
  3. FilesPanel gains a rail form: viewer + film strip + add-files footer. The existing panel stays for the classic wizard.
  4. ScanMediaViewer moves up one level, out of the interpretation panel and into the rail.
  5. Unchanged: the readiness model (the sticky footer reads the same function), FindingsPanel, GroupRoutingPanel, the note, the submit screen, and the whole classic wizard — it does not use StudySurface.

05 · Must hold, whichever we pick

Three things not to break

  1. A failed or detached file still has to shout. The current panel refuses to fold while anything needs attention, and that guard exists because a hidden failed upload is how a broken study reaches submit. In a rail, that means a red marker on the film strip and a notice in the work column — not a smaller dropzone.
  2. “What will be sent” does not say who it is being sent to. Verified: the summary lists exam type, files, scan identifier, patient ID and expert review — no groups — and this flow renders the submit screen with group routing off. Group routing is fixed forever at creation. That is a gap today, independent of this redesign, and it should be closed before any direction that makes routing less prominent.
  3. Changing exam type after findings are answered must keep its dialog. Whatever the exam control becomes, the confirm-what-survives step stays.

06 · Open

Questions I could not settle from the code

  1. Below ~1280, does the media stack above the work or below it? Media-first matches what the interpretation panel does today; work-first gets the learner typing sooner.
  2. In a narrower work column, does exam type stay a 22-tile grid on expand, or become a searchable list? The grid was chosen deliberately because the choice is unrecoverable.
  3. Does the clinical note deserve its own card, or is it the last block of the findings card? It is the same act — saying what you saw.
  4. Should the classic wizard inherit any of this, or stay exactly as it is as the deliberately conservative option?
