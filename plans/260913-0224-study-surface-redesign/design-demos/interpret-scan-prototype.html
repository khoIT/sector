One chain gates the work. Groups and upload are not on it.

Organization narrows which scan types exist; the scan type loads the ontology. Everything else — sharing, uploading — hangs off nothing and can happen whenever. Order the page that way and it collapses to three blocks.

organization ──▶ scan type ──▶ ontology + org forms ──▶ evaluate ──▶ expert review? ──▶ submit
groups upload routing and bytes · gate nothing · block nothing · free to happen at any point

01 · Why the order matters more than the styling

ScanVault ships the pre-flag half of this flow

The legacy create-scan form has an Organization control at the top, behind the GrowthBook flag scans_org-with-forms_all. When it is on, the organization drives three separate fetches:

  • getOrganizationScanTypes(org) — which scan types are offered at all
  • getOrganizationScanTypeItems(org, type) — which ontology those rows come from
  • getOrganizationForms(org) — the dynamic form fields

Changing the organization clears the scan type and every answered finding, because a different org can define a different ontology. When the learner belongs to exactly one organization it is auto-selected and rendered as a plain read-only label; a searchable combobox appears only when there are several.

ScanVault implements the flag-off path, and only that.

It calls the generic /api/scan-type/:id/items, never the org-narrowed /api/scan-type-org/:id/items?organization=. The client has the org-narrowed function and the organizationId field, but the field is created null in use-create-scan-draft.ts and never assigned — five read sites, zero writes. It renders items and drops forms, which the schema comment states outright.

So this is not a dead wire somebody forgot. It is the older of two code paths, shipped whole. Whether to close the gap is a product decision, not a bug fix — and the flag defaults to false in the legacy config, so it may not be on anywhere.

Two consequences for the layout. Organization belongs in the setup row — it is the first gate, and for a single-org learner it costs one label and no interaction. And groups do not belong there for any data reason: a group is { id, name, slug, parent } with no organization on it, a tree of sharing cohorts whose leaves are the default audience. Groups gate nothing. They sit in the setup row only because the choice is unrecoverable after submit and the page's basement is the wrong place for that.

03 · What each decision buys

Six decisions

  1. The setup row is the whole gate, and it comes first. Organization then scan type, in that order, because that is the order the fetches depend on. For the common single-org learner the organization is a label, not a control — one line, no interaction, and the row still reads as two choices. This is the arrangement that makes organizationId wirable at all, whenever the flag is worth turning on.
  2. Scan type is a searchable combobox, not a 22-tile grid. The grid was defended on the grounds that the choice is unrecoverable — but a grid does not make a choice more careful, it just makes it taller. The confirm dialog on switching after answering is what protects that, and it stays.
  3. Groups uses the identical control — but for a different reason. Groups gate nothing: the schema is { id, name, slug, parent }, a tree of sharing cohorts with no organization on it. It sits in the setup row purely because routing is fixed forever at submit, and the page's basement is the wrong home for an irreversible choice. Matching the control makes the row read as one act — set up the study.
  4. Upload is a control, not a zone. One compact button in the setup row, the film strip under the viewer, and the whole surface stays a drop target. With no files the viewer is the dropzone — at viewer size, not a full-width slab at the top of the page.
  5. The ontology is dense rows, media alongside. Label left, every option the definition declares on the right, hairlines between — the shape in your screenshot. The media sticks beside it, because the viewer is only useful while the questions are being answered.
  6. Submit confirms in place; there is no second screen. Everything the old review page restated is already on this one. What a confirm must add is the part that is irreversible — and unlike today's summary, it names the groups.

05 · Care

Three things this must not lose

  • A failed or detached file still has to shout. The strip carries a red marker and the commit bar refuses to read “ready” — a compact upload control must not become a quiet one. This is the single biggest risk in shrinking the files UI.
  • The org forms are still not rendered, and that is the same decision as the organization gate. Your screenshot's “Did you use AI tools in the scan above?” is not part of the AAA ontology — it comes from getOrganizationForms(org), alongside client ID, age, gender, county, referral reason and the GA calculator. ScanVault drops the forms array the response already carries. Turning the organization gate on and rendering those fields are one piece of work, not two, and this layout has the room for them: directly under the findings rows, above the note.
  • Changing scan type after findings are answered keeps its dialog. The combobox is a smaller control, not a looser one.

06 · Open

Four I cannot settle from the code

  1. Is scans_org-with-forms_all on anywhere? It defaults to false in the legacy config and resolves through GrowthBook at runtime, so the real state per environment is not readable from the repo. If it is off everywhere, ScanVault is not behind at all and this is a layout change only. If it is on in production, ScanVault is serving a different ontology than the dashboard for the same learner — and that is the whole ballgame.
  2. If the gate goes in, what happens to a draft saved under another organization? Changing org clears the scan type and every finding. A draft restored days later, after the learner's org membership changed, hits that rule with answers already in it.
  3. Should the note stay above or below the findings? It is drawn below here, as the last thing you say. Some clinicians write context first.
  4. Does the classic wizard stay? It is now the only place the 22-tile grid survives. That is a defensible split — conservative flow, conservative control — or a thing to retire.
