Three decisions

Taken before a line of this was written

Data layer One API, one authorization model. gusi_nodejs_api stays the only thing that touches Mongo and S3; Sector gets a thin read seam there and a harness that replays real production shapes through every schema. No second authorization model. Phase 2 exists because of this.
Home screen Port it properly — four role dashboards, including the two that are dead today. 22 days. +18 over the light alternative, and the largest line in the plan.

Choosing to replace the dashboard rather than sit beside it also settled a question the parity audit had left open. Six items that were arguable scope are now must-builds: mark a study complete or incomplete, correct a submitted expert review, request expert review on an existing scan, the AI Review Generator, reset-upload recovery, and adding or deleting files after submit. There is no other app for a reviewer to go to.

Before anything

Eight authorization guards are commented out on main

gusi_nodejs_api/src/app/course-meta-version/course-meta-version.route.ts

Verified by hand, present on main, introduced 2025-09-09. publish, archive, restore, addApproval, getVersionsForUserGroup, assign/user-course, assign/users and migrate/:userCourseId are all authUser only. Any authenticated account — a learner included — can publish or archive a course version, approve one, or reassign learners between versions.

This is live today, and Sector makes it worse by adding a second client that reaches course versions. Triage before Phase 5 starts. Two more from the same sweep, unverified but specific: any signed-in user can read another user's referral list including email addresses, and an unauthenticated-tier write endpoint ships in the production route table.

The name

Why Sector, and the one I had to kill

ScanVault was outgrowing itself. The app is about to hold courses, quizzes, a gallery and group administration — and Scan Vault is already a module name inside ScanHub, as well as an unreachable tab in the old dashboard. One word, three referents, in every conversation.

CandidateStrategyVerdict
SectorName the artefact — a sector scan is the phased-array wedge Chosen Best mark by a distance. The icon is the product.
BedsideName the practice; POCUS is bedside ultrasound Warmest, weakest as a mark — Core Ultrasound and SonoSim already use the word as descriptive copy.
SonoName the field; the sono root survives all seven locales Legible everywhere, but generic and thin on trademark.
GainName the mission twice: the instrument control, and learning gain Strongest meaning, worst icon, unsearchable.

Killed after a search: Caliper. It was the favourite — the on-screen measurement marks, instantly legible to anyone who has held a probe. But 1EdTech Caliper Analytics is a widely adopted learning-analytics standard, carried by Blackboard, D2L, Instructure and McGraw-Hill. Naming an LMS after it is a collision you live with forever.

No trademark or domain search has been run. That is a real step before the name goes public, and not one this analysis can perform.

The one irreversible mistake: starting course UI before the read seam lands.

Port against today's four-parallel-arrays shape and Sector permanently inherits 553 lines of util.ts, four client-side traversals of one graph, three React Router patterns for one quiz component, and blindness to a fourth nesting shape. None of it is removable later without a second port. It is a scheduling risk, not a technical one — which makes it the easy one to lose to pressure.

The data question

Why "all the real data" is a test, not an architecture

Three things settled it against a second data layer.

  • The client cannot reach S3 at all. src/lib/s3.ts signs media with a CloudFront key pair and presigns objects for ten minutes. The private key is a server secret; direct-to-S3 means moving it into a second service.
  • Authorization is granular permission strings plus wildcards, and the port already mishandles full-access. A second reader is a second place for an authz bug to hide — and there are eight commented-out guards on main showing what that costs.
  • Transactions and the notification side effects live in the API. The scan-notify defect proved that calling a different endpoint silently drops the email, the push and the activity log.

So fidelity becomes something that can fail in CI. The material is already on disk — no step in this plan connects to the production cluster, and refreshing a dump is a read.

The limit, stated rather than glossed

The dumps carry file records, not S3 objects. Media bytes are not reproducible from them. Metadata fidelity is testable today; real-object playback needs staging S3 access, which is an ask, not a task.

Separately urgent, and nothing to do with this port

The broken checkout is live and linked from the expired-course banner. A learner enters a full card number, presses Pay, and gets no order, no error and no navigation. Fix or unlink it in the old app today.

What 126 days buys is not a copy of the dashboard. It is a smaller product: one quiz engine instead of four, one members surface instead of two, one server-resolved outline instead of four client-side traversals, one group schema across the read and write sides. Three of those consolidations are cost-negative inside the port itself.

Risk

Five things that can break the schedule

  1. API capacity is not committed. The two-to-three-day read seam gates roughly 27 of the 126 days. Without an API engineer, phases 6, 7 and 9 have no safe start. Raise this in week one, not week six.
  2. The untyped progress blobs. The contract here is parse-not-cast, and the source schema punts on exactly the two shapes the quiz runner needs. Add 30% to the course-quiz work if they cannot be pinned against the mirror.
  3. GrowthBook is the runtime authority and nobody in this study could read it. Every flag-default drop above rests on code defaults. Ten minutes of dashboard access can falsify several — do that before deleting anything.
  4. Starting course UI before the read seam. The scheduling risk above, which is the easy one to lose to pressure.
  5. Two auth defects that get worse when Sector is the only door. One refresh token per user globally, so a second device signs the first one out; and GET /api/me sits inside the twenty-per-fifteen-minutes-per-IP limiter while the app calls it on every cold boot — so a classroom behind one NAT can exhaust the sign-in budget in twenty page loads.

Still open

Questions the plan does not answer

  1. Is the immutable-snapshot write fix funded, and is it CTP-1016? The read seam does not fix it, and learner progress keeps corrupting until someone does.
  2. What is the production GrowthBook state for the nine flags the drop decisions rest on?
  3. Which of the seven locales have real users? Three surfaces need translating, and only the locales with learners are worth it.
  4. Who owns the certificate maintenance switch? Until it lifts, course completion has no payoff anywhere — worth knowing before phases 6 and 7 spend 23 days.
  5. Where does gusi_scanhub_console live? Every authoring claim in the source reports is inferred from the API contract, never observed.
  6. Is Sector the public name or the internal one? Trademark and domain search still pending.
